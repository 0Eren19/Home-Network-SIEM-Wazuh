# Detection Methodology

## Overview

The detection methodology was designed to validate the ability of the Wazuh SIEM environment to identify security-relevant activities generated within the monitored home-network laboratory.

Controlled security testing was performed against the Windows 10 endpoint, with events collected by the Wazuh Agent and analyzed through the Wazuh platform.

The following detection scenarios were tested:

- Network scanning
- Failed login attempts
- File modification
- User account creation
- User account deletion

## 1. Network Scan Detection

### Objective

Determine whether Wazuh can detect network reconnaissance activity generated by an Nmap scan.

### Test Activity

An Nmap operating system detection scan was performed from the Kali Linux virtual machine against the Windows 10 endpoint.

The activity was performed as a controlled attack simulation.

### Detection

Wazuh successfully detected the reconnaissance activity and generated corresponding security alerts.

### Security Significance

Network scanning is a reconnaissance activity that can provide information about a target system before further attack activity.

Detecting scanning activity can help security analysts identify potential reconnaissance against monitored systems.

### Result

**Status: Detected successfully**

The network scanning activity was detected and analyzed through the Wazuh Dashboard.

## 2. Failed Login Detection

### Objective

### Test Activity

## Validation Approach

Each detection scenario followed a common validation process:

1. Generate a controlled security activity.
2. Allow the Wazuh Agent to collect the resulting endpoint events.
3. Forward the events to the Wazuh Manager.
4. Analyze the events using Wazuh detection capabilities.
5. Store and index the processed events.
6. Review the resulting alerts through the Wazuh Dashboard.
7. Confirm whether the expected activity was detected.
